—- NAT

NAT 只是通过多个内部私有 IP 共享少量公网 IP，大幅缓解了 IPv4 地址不足，但没有“彻底解决”。真正从根本上解决 IPv4 地址空间不足的是 IPv6。

NAT 隐藏了内部网络的真实 IP，外部通常不能直接主动访问内部主机，因此客观上具有一定的隔离、防护作用。但注意：NAT ≠ 防火墙。

NAT 的核心就是修改 IP 报文中的地址。出网时通常修改源 IP，回包时修改目的 IP。
通过静态 NAT/端口映射，可以让外网访问指定的内网服务器。例如把公网 1.1.1.1:80 映射到内网 192.168.1.10:80。

主要作用是实现私有 IP 地址和公网 IP 地址之间的转换。

可以简单理解为：内网很多设备，通过 NAT 共用一个或少量公网 IP 上网。

NAT = 私网地址 ↔ 公网地址转换；核心作用是缓解 IPv4 地址不足。
PAT = IP + 端口转换，让多台主机共享一个公网 IP。

常见 NAT 类型

静态 NAT：一个私网 IP 固定对应一个公网 IP。

动态 NAT：从公网 IP 地址池中动态选择一个地址进行转换。



 



—-防火墙

公司内网 → 防火墙 → Internet

防火墙主要做三件事：

网络隔离：把内部网络与外部网络隔开，避免外部设备随意进入内网。
访问控制：根据 IP 地址、端口、协议、应用等规则决定流量是允许还是拒绝。例如允许员工访问网页的 TCP 443 端口，但禁止外网直接访问内部数据库的 3306 端口。
安全防护：较新的防火墙还可以进行应用识别、恶意流量检测、入侵防御等。

—-logistic模型

Logistic 回归主要用于分类，而不是预测连续数值。

自变量 X 可以有多个，可以是连续或离散特征；目标变量 Y 是类别变量。

年龄(X_1)+收入(X_2)+是否有房(X_3) —>是否违约（Y）

第一步，先像线性回归一样，把各个特征进行加权：z=w_1x_1+w_2x_2+\cdots+w_nx_n+b

第二步，通过 Sigmoid函数（逻辑函数）：把结果压缩到 0～1之间。

自变量 → 加权求和 → Sigmoid → 0～1概率 → 阈值判断 → 分类结果

Logistic回归 = 分类算法 + Sigmoid函数 + 输出0～1概率

Logistic 回归要求目标变量（因变量 Y）是离散的类别变量。

—-测试

白盒测试

白盒测试覆盖方法：

主要检查：

程序中的语句是否都执行过
if 等判断的真、假分支是否都测试过
各个条件是否充分测试
程序的执行路径是否覆盖

常见覆盖方法：

语句覆盖、判定覆盖、条件覆盖、路径覆盖。

语句看“句”，判定看“整体真假”，条件看“各小条件真假”，路径看“所有路线”。

其中，语句覆盖要求最低，发现错误能力最弱；路径覆盖通常最全面。

最可能考点：黑盒测试方法

最常考的是区分几种典型方法：

等价类划分、边界值分析、因果图、错误推测法

其中尤其要掌握 等价类 + 边界值。

例如规定年龄范围 1～120：

等价类：把输入分成 <1、1～120、>120 三类，每类选代表数据测试。
边界值：重点测试边界附近，如 0、1、2、119、120、121。

程序的环形复杂度

(1)控制流图法（边与节点数）：

V(G)=E-N+2P。E是边数，N是节点数，P联通分量，一个单函数，P就是1.

(2)判定节点法（更简便、常用）：

V(G)=P+1，P 是程序中判定节点（分支点）的数量。

1 ~ 10：代码结构清晰、逻辑简单，易于测试和维护。
11 ~ 20：代码较为复杂，存在中等测试与维护风险，建议适度重构。
21 ~ 50：高风险、逻辑混乱，测试难度大，极易出错。
> 50：严重不稳定、几乎无法维护和测试，必须重构



在大型企业信息系统中， 常常需要对数据库进行性能优化以提高系统的响应速度和吞吐量。 请描述至少三种数据库性能优化的常见方法， 并简要解释每种方法的基本原理及其对系统性能可能产生的影响。

参考答案：

1.索引优化：

· 基本原理： 索引是数据库表中一列或多列的值进行排序的一种数据结构， 可以大大加快数据的检索速度。 通过为经常作为查询条件的列创建索引， 数据库系统能够迅速定位到满足条件的记录， 减少全表扫描的次数。

· 对系统性能的影响： 正面影响是显著提高查询速度， 特别是在处理大量数据时效果尤为明显。 但负面影响包括增加写操作的开销（如插入、 更新、 删除时需要维护索引）， 以及占用额外的存储空间。

2.查询优化：

· 基本原理： 通过分析 SQL 查询语句， 找出执行效率低下的部分， 如不必要的全表扫描、 低效的连接操作等， 并通过改写查询、 使用更有效的 SQL 函数或子查询替代等方式来提高执行效率。

· 对系统性能的影响： 优化后的查询能够减少数据库的响应时间， 提升整体系统性能。 但需要注意的是， 过度复杂的查询优化可能导致代码可读性下降， 维护成本增加。

3.数据库配置调整：

· 基本原理： 根据数据库的运行环境和业务需求， 调整数据库的内存分配、 缓存大小、 并发连接数等配置参数， 以达到最佳的性能表现。 例如， 增加缓冲池大小可以减少磁盘 I/O 操作， 提高数据访问速度。

· 对系统性能的影响： 合理的配置调整能够显著提升数据库的处理能力， 减少资源争用， 提高系统稳定性。 然而， 不当的配置可能导致资源浪费或系统不稳定， 因此在调整前需充分评估并测试。

常见的风险应对策略建议你直接记这几个：

风险回避：改变计划，直接避开风险。例如不用不成熟的新技术。

风险转移：把风险责任转给第三方。例如购买保险、项目外包。

风险减轻（损失控制）：降低风险发生概率或发生后的损失。例如增加测试、备份数据。

风险接受/自留：知道存在风险，但选择自己承担。例如风险很小，发生后再处理。

---数据库

三级模式结构：
外模式（子模式或用户模式）是数据库用户能够看见和使用的局部数据的逻辑结构和特征的描述，
二级映像
外模式：用户看到的数据视图
  ↕ 外模式／模式映像  【逻辑数据独立性】
模式：整个数据库的逻辑结构
  ↕ 模式／内模式映像  【物理数据独立性】
内模式：数据的物理存储结构

概念模式是数据库中全部数据的整体逻辑结构的描述，
内模式（存储模式）是数据库在物理存储方面的描述。
数据模型的类型：层次模型(树形结构)、网状模型、关系模型
数据模型三要素：实体、属性和关系

 
三范式
